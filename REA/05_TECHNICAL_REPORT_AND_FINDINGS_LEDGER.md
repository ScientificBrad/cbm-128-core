## 1. Memory and Hardware Architecture Documentation

### 1.1 Dual-Processor & Bus Arbitration Architecture (`Zilog Z80A` + `MOS 8502`)
The Commodore 128 contains two microprocessors sharing the system bus under the control of the **MOS 8722 Memory Management Unit (MMU)** Mode Configuration Register (`$D505` / `MMU_MCR`):
- **Bit 0 = `0` (Hardware Power-On Default):** Selects the **Zilog Z80A** (clocked at 4 MHz effectively / 2 MHz bus phase) and tri-states the MOS 8502. In Bank 0 (`CR` bits 7–6 = `00`), physical `U35` KERNAL ROM offset `0x1000–0x1FFF` (`$D000–$DFFF`) is translated down to Z80 address `$0000–$0FFF` (`z80bios.bin`).
- **Bit 0 = `1`:** Halts the Zilog Z80A and enables the **MOS 8502** (1.02 MHz / 2.04 MHz selectable via `$D030` bit 0).
- **Shared RAM Handoff Stub (`$FFD0–$FFEF`):** Installed by the Z80 during initial boot (`$0097: LDIR` from `$0EE5`), allowing seamless round-trip context switches between the Z80 (`$FFE0–$FFEF`) and the 8502 (`$FFD0–$FFDF`).

### 1.2 MOS 8722 MMU Register Map (`$D500–$D50B` & Always-Visible `$FF00–$FF04`)

| Address | Register | Name | Hardware Function |
|---|---|---|---|
| `$D500` / `$FF00` | `CR` | Configuration Register | Bits 7–6: RAM Bank (`00`=Bank 0, `01`=Bank 1); Bits 5–4: `$C000-$FFFF` (`00`=KERNAL/Editor ROM, `01`=Int Func ROM, `10`=Ext Func ROM, `11`=RAM); Bits 3–2: `$8000-$BFFF` (`00`=BASIC Hi/Monitor ROM, `11`=RAM); Bit 1: `$4000-$7FFF` (`0`=BASIC Lo ROM, `1`=RAM); Bit 0: `$D000-$DFFF` (`0`=I/O Devices, `1`=Char ROM/RAM) |
| `$D501–$D504` | `PCRA–PCRD` | Preconfiguration A–D | Latched bank configurations loaded into `CR` whenever any write occurs to `$FF01–$FF04` (`LCRA–LCRD`) |
| `$D505` | `MCR` | Mode Configuration Register | Bit 7: `40/80 DISPLAY` key sense (`1`=40-col, `0`=80-col); Bit 6: `C64/C128` mode (`0`=C128, `1`=C64); Bits 5–4: `/EXROM` & `/GAME` cartridge sense; Bit 3: `FSDIR` fast serial direction; Bit 0: CPU select (`0`=Z80, `1`=8502) |
| `$D506` | `RCR` | RAM Configuration Register | Bits 3–2: Common RAM enable (`00`=none, `01`=bottom, `10`=top, `11`=both); Bits 1–0: Common RAM size (`00`=1 KB, `01`=4 KB, `10`=8 KB, `11`=16 KB). KERNAL sets `RCR = $04` (Bottom 1 KB `$0000-$03FF` shared across Bank 0 & Bank 1) |
| `$D507–$D508` | `P0L` / `P0H` | Page 0 Relocation | Relocates CPU Zero Page (`$0000-$00FF`) to any physical page and RAM bank |
| `$D509–$D50A` | `P1L` / `P1H` | Page 1 Relocation | Relocates CPU Stack Page (`$0100-$01FF`) to any physical page and RAM bank |
| `$D50B` | `VR` | Version Register | Returns `$20` (2 × 64 KB RAM banks = 128 KB, MMU revision 0) |

### 1.3 Dual Video Architecture (`MOS 8564/8566 VIC-IIe` + `MOS 8563 VDC`)
1. **40-Column Display (`VIC-IIe` at `$D000–$D030`):**
   - Backwards compatible with the C64 6567/6569 VIC-II, adding `$D02F` (3 extra keyboard scan output lines for keypad/top-row keys) and `$D030` (Bit 0 = 2 MHz mode, Bit 1 = screen blanking/test bit).
   - Uses screen matrix at `$0400–$07E7` in RAM Bank 0 and Color RAM at `$D800–$DBFF`.
   - Generates the C128's primary 60 Hz/50 Hz system IRQ via Raster Compare (`$D012` / `$D019` / `$D01A`), unlike the C64 which used CIA1 Timer A.
2. **80-Column RGBI Display (`8563 VDC` at `$D600–$D601`):**
   - Accessed strictly via two indirect ports: `$D600` (Address/Register Select on write; Status Register on read where Bit 7 = `Ready` and Bit 5 = `VBlank`) and `$D601` (Internal Register R0–R37 Read/Write).
   - Owns 16 KB (expandable to 64 KB) of dedicated VRAM isolated from the CPU bus, accessed via R18/R19 (Update Address High/Low) and R31 (VRAM Data), with hardware block fill/copy triggered by writing word count to R30 (controlled by R24 bit 7 and R32/R33 copy source).
   - Initialized during boot by `ED_JINIT80` (`$C027 -> $CE0C`), which copies the 8 KB Character Generator ROM (`390059-01`) into VDC VRAM `$2000–$3FFF`.

## 3. Record of Limitations, Host Obstacles & Unfinished Features

In accordance with Section 1 (Item 16) and Section 3 ("If a task cannot be completed, document the obstacle precisely and continue with independent work that remains possible"):

1. **Host Environment `.NET SDK` Absence:**
   - Inspection of the Windows host (`dotnet --info`) confirmed that while the .NET Runtimes (`Microsoft.NETCore.App 8.0.13` and `10.0.5`) are installed, **no .NET SDK (`No SDKs were found`) or `csc.exe` compiler is installed on the host machine**.
   - Consequently, both a complete **.NET 8 C# implementation** (`src/Cbm128.Core/` and `src/Cbm128.Emulator/`) and a complete, 100% functional **Python 3.10 implementation** (`src/cbm128/` and `tests/test_cbm128.py`) have been delivered so that genuine execution of the original ROM instructions is immediately verifiable on the current machine as well as ready to build on any machine with the .NET 8 SDK.
2. **Emulator Scope Boundaries:**
   - **External 1571/1541 Disk Drive & Datassette Peripherals:** The IEC serial bus and CIA1 fast-serial shift register (`$DC0C`/`$DC0D`) are emulated at the hardware register level (correctly signalling "Device Not Present" on boot so `BOOT_CALL` cleanly falls through to `READY.`), but a separate 6502-based 1571 disk drive CPU/GCR controller is not attached by default.
   - **Cycle-Exact VIC-IIe Badline / Sprite Multiplexing & Audio Output:** VIC-IIe 40-column character matrix rendering, raster counter, and raster IRQ generation (`$D011`/`$D012`/`$D019`/`$D01A`) and 8563 VDC 80-column VRAM/block operations are implemented for full firmware and application execution; cycle-accurate DMA badline stealing and host PCM audio output from SID registers (`$D400–$D418`) are documented as future extensions.
